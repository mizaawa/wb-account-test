# 凭证导入、测活与额度查询

## 修复原因

v2.0.3 把所有 `accounts` 导出都放入离线清单，主动丢弃令牌；主按钮依赖在线账号数，因此即使导出包含有效凭证也被禁用。v2.0.4 按记录是否含令牌分流，不通过强制启用空队列按钮来掩盖问题。

## 上游提取范围

参考用户提供的 workbuddy2api-hub 本地快照，只适配账号相关功能：

| 上游函数或定义 | 本项目落点 |
| --- | --- |
| `normalise_import_row`、`jwt_uid`、`normalize_epoch` | `web/src/api.js` 字段映射、JWT sub、秒/毫秒到期时间 |
| `realm_evidence`、`domain_for_realm` | issuer 优先于 domain，再使用导出地区与默认地区；跨区域名纠正 |
| `fetch_account_profile` | `/console/account` 校验身份及 UID 一致性 |
| `_refresh_locked`、`CN_CHAT_BASE_DEFAULT` | 单次测活串行刷新；国内固定 `copilot.tencent.com`、国际固定 `www.workbuddy.ai` |
| `_fetch_credits_cn_detailed`、`_fetch_credits_fallback` | 额度摘要优先，资源包回退；使用官方剩余额度字段 |
| `_fetch_credits_enterprise` | 企业/静态 API Key 分流，并发送企业与租户头 |

未复制上游自动任务、聊天调用、密钥落盘、设备指纹或任意目标代理。

## 执行顺序

1. 浏览器读取 JSON/JSONL，不请求网络；清单中的凭证记录与无令牌记录分流。
2. 合并同地区、同 UID 的账号；无 UID 的不透明令牌按令牌去重。后导入凭证更新旧记录并置为待测活。
3. 点击「凭证测活」，确认同源服务版本；每批最多 8 个账号同时执行。
4. 若本地到期时间已过则刷新；否则先验证资料，认证失败时最多刷新一次并重试。刷新只更新页面内存。
5. 身份成功后查询个人/企业额度；缺少身份字段或额度结构不能显示为正常。
6. 按钮恢复可点击，可再次测活全部账号；失败项有独立批量/单项重试。

HTTP 401/403 或业务认证码表示官方拒绝，不代表导入错误；无刷新令牌时必须重新导出。JWT 的 exp 未到并不能证明服务器仍接受令牌。网络错误、取消、版本不匹配与认证失败分别展示。

## 回归与真实文件验收

`npm test` 覆盖字段解析、地区判断、业务码刷新、轮换保留、缺失响应结构、企业分流、超长 JSONL。`npm run test:browser` 在 Chromium/WebKit 用纯虚构凭证逐一验证三种文件形态，随后验证混合导入、重叠账号合并、更新凭证、点击测活、额度显示及无本地持久化。

用户真实凭证只能在明确授权的本机验收中使用；不写入自动化夹具、截图公开附件、仓库或 Actions 日志。真实响应的成功与拒绝应分别记录，不把 mock 回归当作真实账号成功证明。

## 2026-11-24 本机验收结果（脱敏）

三个用户文件在本机浏览器分别通过文件选择器导入并点击「凭证测活」，没有模拟官方接口。随后进行三文件同时导入与测活。

| 输入 | 导入数 | 资料与额度成功 | 官方拒绝 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 导出清单 A | 1 | 0 | 1 | 资料 HTTP 401；文件无刷新令牌 |
| 导出清单 B | 3 | 2 | 1 | 两个账号资料/额度均 HTTP 200；剩余额度均为 0；拒绝项与 A 重复 |
| 蛇形字段数组 C | 1 | 0 | 1 | 资料、刷新均 HTTP 401 |
| 三文件混合 | 4（已去重） | 2 | 2 | 按钮恢复可点击，完成进度 100% |

浏览器无页面脚本错误，导入时无账号请求，LocalStorage/SessionStorage 均为空。截图中的账号标识已遮盖，仅保存到被 Git 忽略的本地验收目录。HTTP 401 是真实拒绝结果，不作为“程序成功验证账号”的证明；两个正常账号剩余 0 也不意味着还有可用模型额度。

## 回滚

容器可固定到 v2.0.3；源码可 revert 本次修复提交。刷新页面清除内存账号。原始导入文件始终只读，刷新令牌不会写回源文件。
